# KLEANFW 0.2.0

Second release of KLEANFW, a custom firmware for the **Quansheng UV-K1 /
UV-K5 V3 (PY32F071 + BK4829 only)**. It is a modified version of
[GOGUFW 3.6.2](https://github.com/Gogu-Qs/GOGUFW-UV-K1-Messenger) by Gogu-Qs
(F4HWN 6.3.0 base) and an independent project, not affiliated with or
endorsed by Gogu-Qs, F4HWN or Quansheng.

Before this release the whole firmware was reviewed against the BK4829
register table: the driver, every register write outside it (apps included),
the flash write paths and the serial command parser. The release files were
then replaced with a build that also includes the fixes of a full code review
(below): if you downloaded 0.2.0 before, download it again.

## Highlights

- **HOP follows the transmitter's clock**: from the first 8 s resync of an
  over, the receiver measures the clock difference to the transmitter and
  tracks it, so long overs stay aligned even between radios whose clocks
  differ. Radios without drift behave exactly as before.
- **HOP and battery save**: while listening to a HOP channel (MsgRx ON,
  VOX OFF), `BatSav` does not sleep, so the ~0.2 s seed burst at the start of
  an over is not missed. Other channels keep the normal battery save. This
  costs battery on HOP channels, as `BatSav` OFF does.
- **Spectrum (F+5)**:
  - MR mode sweeps the scan list of the channel on screen (`ChList`); key 4
    cycles `ALL`, each list, then `OFF` (every channel).
  - The sweep filter now uses the full REG_43 value (it was cut to 8 bits,
    inherited from F4HWN): with 25 kHz steps it is 7 kHz instead of 4 kHz, so
    signals off the step centre show up. The noise floor reads ~2 dB higher;
    AUTO recalibrates, a manual trigger does not.
  - Spectrum always listens in clear; the channel's scrambler comes back on
    exit.
- **Fixes**:
  - A fixed-scrambler channel no longer receives inverted after a HOP
    reception on another channel (channel change or Dual Watch).
  - The Messenger no longer stays "busy" for 1.2 s after every HOP burst.
  - USB/serial EEPROM commands ignore sizes that do not fit their buffers
    (a host could overflow the stack; CHIRP is not affected).
- Smaller image: libc start files and unused printf conversions removed.
- **Full code review fixes** (driver and radio setup against the BK4829
  table, USB/serial and Messenger input, storage, menus):
  - USB: no more ~0.1 s stall every 64 CHIRP blocks; an odd-sized read and
    oversized slot-write chunks can no longer hang the radio.
  - Key-action menus (F1/F2/M Long) no longer read a garbage pointer for
    actions this build lacks (ALARM, 1750Hz, BACKLIGHT... set by CHIRP), and
    a stored NOAA channel no longer reads past the band tables.
  - Messenger: RESEND no longer stores an empty text; an ACK or PONG for
    another station no longer marks our message as delivered.
  - Menus: keypad entry honours each menu's minimum, `BatCal` can be typed
    (4 digits), cancelling `SetCtr` keeps the saved contrast, PriCh1/PriCh2
    no longer jump to None.
  - Spectrum scan-range mode no longer sweeps a fraction of the range with
    very small steps.
  - TX compander follows the TX VFO with cross-band; airband channels get
    their TX offset cleared; smaller timing and display fixes.

## Before you flash

- Back up the radio and its calibration with CHIRP and keep a DFU recovery
  image.
- First boot after updating: the version reset clears KEY_LOCK, MENU_LOCK,
  SET_KEY and SET_INV and turns `SetRxG` back ON.
- Use only the KLEANFW 0.2.0 CHIRP module (model **UV-K1 / UV-K5 V3 KLEANFW**).
  The EEPROM layout is the same as 0.1.0.
- Apps are unchanged from 0.1.0 (same app API). Unzip `FM-Search-Apps.zip`
  and install both FM apps and Search.app with UV Studio (Apps page). GitHub
  does not accept `.app` attachments, so the apps come zipped.

## Not yet tested on a radio

The changes in this release were checked by code review, builds and a host
simulation (HOP clock tracking), not on air. Useful checks, and reports in
[GitHub Issues](https://github.com/AislanJefferson/KLEANFW/issues):

1. A fixed-scrambler channel received right after a HOP over is clear.
2. A HOP over longer than 16 s stays intelligible around each resync.
3. `BatSav` 1:4 on a HOP channel: the radio does not sleep and overs starting
   unexpectedly are descrambled from the start.
4. F+5 with 25 kHz steps: peaks off the step centre show up; opened from a
   scrambled channel, Spectrum listens in clear.
5. Sending a message right after hearing a HOP over goes out without delay.
6. CHIRP download and upload over USB complete with no pause at the 12th
   block and every 64 blocks after.
7. Messenger with three radios: an ACK from C to B does not mark A's message
   with the same number as delivered.
8. Keypad entry: `0` in `ScList` is ignored, `2000` in `BatCal` is accepted,
   EXIT from `SetCtr` restores the contrast.
9. Spectrum scan-range over 2 MHz with step 0.01 kHz: the step moves up and
   the whole range is swept.
